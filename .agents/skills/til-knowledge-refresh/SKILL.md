# TIL 지식 갱신

기존 문서의 유효한 지식과 기록 목적을 보존하면서 변경이 필요한 주장만 고친다. 경로와 명령은 저장소 루트 기준이다.

## 범위와 기준

- 지정된 문서를 읽는다. 주제만 주어졌으면 `rg --files docs`와 키워드 검색으로 대상을 찾고 가장 관련 있는 파일부터 확인한다.
- 사용자가 "검토만", "문제점 알려줘"라고 하면 파일을 수정하거나 publish하지 않는다. "최신화해줘"는 확인된 오류와 누락을 문서에 반영하는 요청으로 처리한다.
- 문서가 현재 사용법인지, 특정 버전 가이드인지, 과거 장애 기록인지 확인한다. 최신 릴리스가 나왔다는 이유만으로 과거 환경과 당시 결과를 지우지 않는다.
- 사용자가 지정한 버전이 우선이다. "최신"이면 공식 릴리스 자료에서 조사 시점의 안정 버전을 확인하고 preview·실험 기능을 구분한다. 임의로 사용자 환경의 버전을 바꾸지 않는다.

## 주장 단위로 확인

버전에 영향을 받는 설명을 먼저 추린다. 작업 메모에 아래처럼 근거와 조치를 대응시키되 별도 보고서 파일은 요청받았을 때만 만든다.

| 기존 주장 | 대상 버전의 공식 근거 | 판단과 조치 |
| :--- | :--- | :--- |
| 기능 지원, 기본값, 제한, 권장 명령 등 | 실제 읽은 문서·릴리스·소스 URL | 유지 / 수정 / 버전 조건 추가 / 확인 불가 |

- 공식 문서, 릴리스 노트, 변경된 코드·테스트 순으로 필요한 근거를 찾는다. 검색 결과의 날짜를 기능 출시일이나 수정 버전으로 해석하지 않는다.
- 한 버전의 동작을 모든 버전에 일반화하지 않는다. 변경 전후를 확인했을 때만 버전 경계를 적는다.
- 프로젝트 안에서 같은 API·주장을 검색해 직접 관련된 설명이 모순되는지 확인한다. 관련 없는 문서까지 일괄 개편하지 않는다.
- 접근할 수 없는 출처나 재현하지 못한 주장은 확인 불가로 남긴다. 확인일만 오늘로 바꿔 최신 문서처럼 보이게 하지 않는다.

## 내용 반영

- 맞는 설명과 독자의 이해에 필요한 예제를 유지하고 잘못된 문단을 직접 정정한다. 끝에 주의문만 덧붙여 서로 모순되는 설명을 남기지 않는다.
- 과거 기록은 당시 환경을 유지하고, 현재 적용 시 달라지는 점을 구분해 보충한다. 특정 버전 안내라면 새 버전과의 차이만 필요한 만큼 추가한다.
- API·설정이 달라졌으면 본문과 예제를 함께 고친다. 성능·동시성·트랜잭션 설명은 전제 조건과 실패 조건을 함께 확인한다.
- 실제 확인 범위에 맞춰 기준 버전·확인일·출처를 기록한다. 일부 절만 조사했다면 문서 전체를 검증했다고 표시하지 않는다.
- 파일명이나 제목을 바꿔야 하면 기존 파일명·앵커로 들어오는 링크를 `rg -n -F`로 찾아 함께 수정한다. 최신화를 이유로 불필요하게 이동하지 않는다.

## 완료하기

편집한 경우 `til-doc-verify`로 문서 구조와 예제를 검증하고, 원격 반영은 `git-workflow`를 따른다. 검토만 요청받았다면 발견 사항과 근거를 전달한다.

결과는 변경한 주요 주장, 기준 버전과 출처, 실행한 검증, 남은 불확실성을 중심으로 짧게 설명한다. "전체 최신화 완료"라는 표현은 실제로 확인한 범위에만 사용한다.
