# Java Effectively Final

**Effectively Final**은 Java 8에서 도입된 개념으로, `final` 키워드가 명시적으로 선언되지 않았더라도 초기화 이후 값이 변경되지 않아 사실상 `final`과 동일하게 취급되는 지역 변수를 의미합니다.

---

## 1. 배경: 왜 필요한가?

Java 8 이전에는 익명 내부 클래스에서 외부의 지역 변수를 참조하려면 반드시 해당 변수를 `final`로 선언해야 했습니다. 람다(Lambda)의 도입과 함께 이러한 번거로움을 줄이기 위해, 컴파일러가 변수의 변경 여부를 파악하여 자동으로 `final`처럼 취급해 주는 기능이 추가되었습니다.

## 2. 조건 및 특징

변수가 다음과 같은 조건을 만족하면 Effectively Final로 간주됩니다.
*   `final`로 선언되지 않았음.
*   초기화된 후 단 한 번도 값을 재할당하지 않았음.
*   람다식이나 익명 내부 클래스 내부에서 사용됨.

```java
int number = 10; // final 키워드가 없지만 값이 바뀌지 않으므로 Effectively Final
Runnable r = () -> System.out.println(number); // 사용 가능

int count = 5;
count = 10; // 재할당 발생
// Runnable r2 = () -> System.out.println(count); // 컴파일 에러 발생!
```

## 3. 제약의 이유: 변수 캡처링(Variable Capturing)

지역 변수는 **스택(Stack)** 영역에 할당되며 메서드 종료 시 소멸합니다. 반면 람다나 익명 객체는 **힙(Heap)** 영역에 생성되어 더 오래 생존할 수 있습니다.
이를 위해 람다는 외부 변수의 값을 자신의 영역으로 **복사(Capture)**하여 사용합니다.

이때 발생할 수 있는 문제는 다음과 같습니다.
1.  **데이터 불일치**: 원본 변수의 값이 바뀌면 람다가 복사해간 값과 달라질 수 있습니다.
2.  **스레드 안전성**: 멀티스레드 환경에서 지역 변수의 값을 변경하려고 하면 동기화 문제가 발생합니다.

Java는 이러한 복잡성을 피하고 안정성을 확보하기 위해 "변경되지 않는 변수"만 캡처할 수 있도록 제한합니다.

## 4. 우회 방법

만약 람다 내부에서 값을 변경해야 한다면, 다음과 같은 방법을 사용할 수 있으나 권장되지는 않습니다.
*   **배열 사용**: `final int[] res = {0};` 처럼 배열의 요소를 변경.
*   **Wrapper 객체**: 값을 감싸는 객체를 만들어 필드 값을 변경.
*   **인스턴스 변수 활용**: 지역 변수가 아닌 클래스의 필드(Field)는 이 제약에서 자유롭습니다. (힙 영역에 존재하기 때문)

---

## 5. 결론

Effectively Final은 개발자의 편의성을 높이면서도, JVM의 메모리 구조와 멀티스레드 환경에서의 안정성을 지키기 위한 중요한 제약 사항입니다. 람다를 사용할 때는 외부 지역 변수가 의도치 않게 변경되지 않도록 주의해야 합니다.
