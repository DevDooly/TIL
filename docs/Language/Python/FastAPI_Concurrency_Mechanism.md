# FastAPI의 동시성(Concurrency) 처리 메커니즘

FastAPI가 여러 요청을 동시에 처리하는 방식과 `async def` 및 `def`의 내부 동작 차이를 상세히 정리합니다.

---

## 1. 핵심 개념: 비동기(Async)와 멀티스레드

FastAPI는 Python의 `asyncio`를 기반으로 하며, 상황에 따라 **비동기 이벤트 루프**와 **스레드 풀**을 적절히 혼합하여 사용합니다.

### 🔹 `async def` (비동기 엔드포인트)

* **동작**: 단일 스레드의 **이벤트 루프**에서 실행됩니다.
* **핵심**: `await`를 사용하는 비동기 작업(I/O 대기 등)이 발생하면, 제어권을 루프에 넘겨 다른 요청을 처리하도록 합니다.
* **장점**: 매우 적은 메모리와 CPU 리소스로 수만 개의 동시 연결을 처리할 수 있습니다.
* **주의**: 내부에서 `time.sleep()`과 같은 **블로킹(Blocking) 코드**를 사용하면 전체 서버의 응답이 멈춥니다.

### 🔹 `def` (일반 엔드포인트)

* **동작**: FastAPI가 내부적으로 사용하는 **별도의 외부 스레드 풀(Thread Pool)**에서 실행됩니다.
* **핵심**: 비동기를 지원하지 않는 라이브러리를 쓰거나 블로킹 코드가 포함된 경우에 사용합니다.
* **장점**: 엔드포인트 내부 로직이 메인 이벤트 루프를 방해하지 않으므로 안정적입니다.
* **특징**: 전통적인 멀티스레드 방식과 유사하게 동작합니다.

---

## 2. 요청 처리 흐름도

여러 요청이 동시에 들어오는 경우 FastAPI(ASGI 서버 포함)는 다음과 같은 흐름으로 처리합니다.

1. **요청 수신**: ASGI 서버(Uvicorn 등)가 대량의 소켓 연결을 비동기로 수용합니다.
2. **함수 타입 판별**: FastAPI 라우터가 해당 함수가 `async def`인지 확인합니다.
3. **스케줄링**:
    * **Async**: 이벤트 루프에 등록되어 협력적 멀티태스킹 방식으로 처리됩니다.
    * **Sync (Normal def)**: `anyio` 스레드 풀로 작업을 위임합니다.
4. **병렬성 확보**: `uvicorn --workers N` 옵션을 통해 여러 개의 워커(프로세스)를 실행하면, 멀티코어 CPU를 활용한 진정한 병렬 처리가 이루어집니다.

---

## 3. 상황별 권장 패턴

| 케이스 | 권장 선언 | 비고 |
| :--- | :--- | :--- |
| **현대적인 비동기 DB 드라이버 사용** | `async def` | 최상의 성능 발휘 |
| **외부 API 비동기 호출 (httpx 등)** | `async def` | I/O 대기 효율 극대화 |
| **파일 시스템 I/O (블로킹)** | `def` | 메인 루프 차단 방지 |
| **비동기를 지원하지 않는 레거시 라이브러리** | `def` | 스레드 풀을 통한 안전한 처리 |
| **CPU 집약적인 무거운 연산** | **Celery/RQ** | 웹 서버 내부가 아닌 별도 워커로 분리 권장 |

---

## 4. 요약

FastAPI는 **"비동기로 짤 수 있는 것은 비동기로(`async def`), 그렇지 않은 것은 자동으로 멀티스레드로(`def`)"** 처리해 주는 영리한 프레임워크입니다. 

* I/O Bound 작업이 많다면 `async def`를 적극 활용하여 동시성을 높이세요.
* 함수 내부에서 어떤 방식을 쓸지 확신이 없다면, 이벤트 루프를 멈추지 않는 `def`를 사용하는 것이 더 안전할 수 있습니다.
